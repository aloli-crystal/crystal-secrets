== v0.3.0 — 2026-05-10

=== Added — five new subcommands (lot 1 of the README roadmap)

* `secrets delete -n VAULT -k KEY` (alias `rm`) — remove a key from a
  vault. Errors with exit code 1 if the key is absent.
* `secrets edit -n VAULT` (alias `e`) — decrypt the vault into a
  mode-0600 tempfile, spawn `$EDITOR` (default `vi`), validate the
  edited buffer is still valid TOML, re-encrypt. Tempfile is wiped
  (best-effort) and deleted whether the editor succeeded or not. If
  the user exits the editor non-zero, the vault is left untouched.
* `secrets rotation -n VAULT` (alias `r`) — re-encrypt the vault under
  the current master key. Useful when the ciphertext file has leaked:
  a fresh nonce gives a new ciphertext for the same plaintext, so
  backups from before the rotation cannot be confused with the
  current canonical state. Will pick up the latest `recipients.toml`
  once v0.4.0 ships multi-recipients.
* `secrets diff -n VAULT --against PATH.age` (alias `df`) — compare
  the current vault plaintext against another encrypted vault file
  (typically a previous git checkout). Both must decrypt with the
  current master key. Output is a unified diff via `diff(1)`. Both
  decrypted buffers go through mode-0600 tempfiles, wiped + deleted
  in `ensure`.
* `secrets log -n VAULT` (alias `l`) — print the audit log of a
  vault.

=== Added — append-only per-vault audit log

New module `Secrets::Audit` (`src/secrets/audit.cr`) exposes:

* `Audit.log(vault, op, key=nil)` — append a tab-separated line
  `<RFC3339 UTC> \t <user> \t <op> \t <key|->` to
  `${XDG_CONFIG_HOME:-~/.config}/secrets/audit/<vault>.log`,
  mode 0600.
* `Audit.read(vault)` — return the lines as an array of strings.

`set`, `delete`, `vault create`, `edit` and `rotation` all log their
mutations through this module, giving the operator a "when did I
last touch this vault, and why?" trail.

The log is append-only in spirit but not tamper-proof — an attacker
with write access to the log file can edit it. The intent is
operator-side audit, not security boundary.

=== Added — `Secrets::Editor` helper

New module `src/secrets/editor.cr`. Spawns `$EDITOR` (or `$VISUAL`,
or `vi`) on a mode-0600 tempfile and returns the edited buffer.
Used by `edit_cmd` but also intended for the upcoming `secrets env`
verb (lot .env, v0.5.0). Wipes the tempfile in `ensure` regardless
of editor exit code.

=== Refactor

* `Secrets::XDG_CONFIG_HOME` and `Secrets::CONFIG_DIR` are now
  top-level constants in `src/secrets.cr`. The CLI and the audit
  module both read from these.
* `cli.cr` gets two new private helpers: `parse_vault_only_args`
  (for commands that only need a vault name) and `vault_path` (used
  by edit, rotation, diff, and the existing read/write_vault).

=== Tests

* `spec/audit_spec.cr` — 4 examples covering log creation, append
  semantics, missing-vault behaviour, and 0600 file mode.
* `spec/editor_spec.cr` — 4 examples covering successful edit,
  no-op edit, non-zero editor exit, and tempfile cleanup.
* Total: 31 examples, 0 failures.

== v0.2.6 — 2026-05-10

=== Changed

The repo was renamed from `aloli-crystal/crystal-secrets` to
`aloli-crystal/secrets` in v0.2.2, but the legacy name lingered in
many places: 12 hardcoded `crystal-secrets` strings in CLI banners,
help text and error messages; the default vault directory at
`~/.config/crystal-secrets/vaults`; and most importantly the Keychain
service identifier `dev.aloli.crystal-secrets`. v0.2.6 finishes the
rename and ships a transparent migration so existing users notice
nothing.

* CLI banners, help text, error messages and the binary detection in
  `PROGRAM_NAME` all switched from `crystal-secrets` to `secrets`.
* `DEFAULT_VAULT_DIR` is now `${XDG_CONFIG_HOME:-~/.config}/secrets/vaults`
  (was `crystal-secrets/vaults`). `XDG_CONFIG_HOME` is honoured
  (closes the gap with `feedback_xdg_config_convention.md`).
* Keychain service id is now `dev.aloli.secrets` (was
  `dev.aloli.crystal-secrets`).

=== Migrations (transparent, idempotent)

* **Vault directory** — at every command, if `~/.config/secrets/vaults`
  is absent and `~/.config/crystal-secrets/vaults` exists, the latter
  is renamed to the former. The empty parent dir is deleted.
* **Keychain entry** — `MasterKey.read` and `MasterKey.generate!`
  call `KeychainMacOS.migrate_legacy_if_needed!` first: if the new
  service id has no entry but the legacy one does, the value is
  copied to the new service then the legacy entry is deleted. Both
  operations are no-ops if the user is already on the new layout.

Both migrations leave no trace on a fresh install or for users
already on v0.2.5 with the new paths/service.

=== Tests

* +4 specs covering the Keychain migration (no-op, copy, both-exist
  precedence). Fake `security` script extended with a stateful mode
  in `spec/keychain_macos_spec.cr` so multi-step migration sequences
  can be asserted end-to-end. Total: 23 examples, 0 failures.

== v0.2.0 — 2026-04-28

Wires up the official `aloli-crystal/toml` v0.1 and
`aloli-crystal/diceware` v0.1 shards. The local v0.1
implementations are removed from this repo and replaced by the
upstream dependencies.

* **`CrystalSecrets::Diceware` removed** — replaced by the
  top-level `Diceware` module from `aloli-crystal/diceware`.
  Same wordlist identifiers (`:eff_long`, `:fr_mbelivo_5d`), same
  `:auto`, `:manual`, `:hybrid` modes. Embedded wordlist files are
  no longer in this repo.
* **`CrystalSecrets::TomlCodec` removed** — replaced by the
  `TOML::Document` class from `aloli-crystal/toml`. The
  vault now benefits from **byte-identical round-trip** and
  **comment preservation** : a manual annotation
  `API_KEY = "..." # rotated 2026-04-28` survives a programmatic
  `crystal-secrets set` of another key. The `set_with_comment`
  method is also exposed via the API for future commands.
* **CLI**: `get`, `set`, `list` now operate on `TOML::Document`
  directly via `doc.string?`, `doc.set`, `doc.to_h`. The
  `lookup_key` / `set_key` helpers in CLI are gone — TOML.cr's
  dotted-path lookups (`"stripe.secret_key"`) handle that.
* No breaking change for end users: existing `*.toml.age` vaults
  keep parsing as before.

== v0.1.0 — 2026-04-28

Initial release. macOS-only, single-user, single-recipient.

* **Diceware** module (local) — generates passphrases from two
  embedded wordlists : EFF Large (English, 7776 words) and
  mbelivo 5d (French, 7776 words). Three sourcing modes :
  `:auto` (`Random::Secure`), `:manual` (caller supplies dice
  rolls), `:hybrid`. Will be replaced by `aloli-crystal/diceware`
  when published.
* **KeychainMacOS** — shell-out to `/usr/bin/security` for
  `add-generic-password`, `find-generic-password`,
  `delete-generic-password`. Secret values fed via stdin, never
  argv.
* **Vault** — shell-out to `age(1)` for single-recipient
  encrypt/decrypt (ASCII-armored). `openssl enc` (PBKDF2 600 000
  iterations, AES-256-CBC, SHA-256) for the passphrase recovery
  paper, because `age -p` requires an interactive terminal.
* **TomlCodec** — parses via `crystal-community/TOML.cr`, custom
  serializer that emits `KEY = "value"` lines and `[section]`
  blocks. Multi-line values via `'''…'''` literals. Comment
  preservation will land with `aloli-crystal/toml`.
* **MasterKey** — wraps `age-keygen` to produce the operator's
  age keypair, store the private key in Keychain, recover the
  public key with `age-keygen -y`.
* **Recovery** — `export(identity, passphrase) -> paper` and
  `import(paper, passphrase) -> identity` for the disaster
  scenario where iCloud Keychain itself is unavailable.
* **CLI** — `init`, `vault create`, `get`, `set`, `list`,
  `master-key export/import`, `version`. All long flags have
  short equivalents per Aloli convention.
* **50 tests** (Diceware 23, Keychain 8, Vault 6, TomlCodec 8,
  Recovery 5).
