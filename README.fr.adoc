= crystal-secrets

image:https://github.com/aloli-crystal/crystal-secrets/actions/workflows/ci.yml/badge.svg[CI,link=https://github.com/aloli-crystal/crystal-secrets/actions/workflows/ci.yml]

Gestion des secrets pour l'écosystème Crystal Aloli : un coffre
TOML chiffré avec `age`, une clé maître stockée dans le Keychain
macOS (synchronisée entre Macs via iCloud), un code de recovery
papier protégé par une passphrase Diceware en filet de sécurité.

Version anglaise : link:README.adoc[README.adoc].

== État : v0.1 (initiale, mono-utilisateur macOS uniquement)

Ce shard est la base du système de secrets Aloli décrit dans
`prod-crystal/CRYSTAL-SECRETS-SPECS.adoc`. La v0.1 couvre la
boucle quotidienne de l'opérateur sur son Mac :

* `init` génère une paire de clés `age`, propose une passphrase
  Diceware, imprime la clé publique et le code de recovery papier.
* `vault create / get / set / list` pour l'accès quotidien.
* `master-key export / import` pour le flux de recovery papier.

Hors périmètre v0.1 (prévu en v0.2+) :

* **Coffres multi-recipients** (partage équipe). v0.1 = recipient
  unique (la clé de l'opérateur).
* **Mode agent SSH** (le coffre `ssh-keys.age` + l'agent en
  mémoire qui sert le protocole ssh-agent v2).
* **Backends d'autres OS** (Secret Service Linux, Credential
  Manager Windows, fichier+passphrase FreeBSD). v0.1 = Keychain
  macOS uniquement.
* Sous-commandes **rotation, delete, edit, diff/log**.
* Migration vers **`crystal-toml`** et **`crystal-diceware`** quand
  ces shards seront publiés. v0.1 les embarque en interne.

== Installation

[source,shell]
----
brew install age              # dépendance runtime requise
shards install
crystal build src/cli.cr -o crystal-secrets --release
sudo install -m 0755 crystal-secrets /usr/local/bin/
----

== Récupération (après perte du Mac)

[source,shell]
----
# Sur le nouveau Mac, si la restauration iCloud n'est pas dispo :
$ crystal-secrets master-key import
Paste the recovery paper, then Ctrl-D :
-----BEGIN CRYSTAL-SECRETS RECOVERY-----
U2FsdGVkX1+abc...
-----END CRYSTAL-SECRETS RECOVERY-----
^D
Passphrase (hidden): ●●●●●●●●●●●
master key restored. Public key:
    age1abc123...
----

En pratique, **iCloud Keychain** fait le travail automatiquement :
la clé maître suit l'utilisateur sur le nouveau Mac sans qu'il
ait à retaper quoi que ce soit. Le papier est le filet de sécurité
ultime, utilisé uniquement si iCloud lui-même est indisponible.

== Discipline de la clé en mémoire

* La clé maître n'est **jamais** passée en argument de ligne de
  commande (visible via `ps`).
* Les valeurs des secrets ne sont **jamais** passées via argv non
  plus ; `set` lit la valeur depuis stdin (cachée quand STDIN est
  un terminal).
* La clé privée age est passée à `age(1)` via un fichier temp en
  mode `0600`, supprimé dès le retour d'`age`.
* Sur disque, le coffre est `<env>.toml.age` (payload TOML chiffré
  par age). La clé maître ne touche pas le disque sauf dans le
  blob Keychain (géré par macOS).
* Le papier de recovery = blob chiffré openssl ; la passphrase est
  l'unique protection du papier. Ranger les deux dans le même
  coffre physique pour ne pas dupliquer le risque.
